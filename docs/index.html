Wprowadzenie

Witaj w dokumentacji Habits Tracker - zaawansowanej aplikacji webowej do śledzenia codziennych nawyków i monitorowania postępów w doskonaleniu się.

Czym jest Habits Tracker?

Habits Tracker to nowoczesna, responsywna aplikacja webowa zbudowana z Vanilla JavaScript i Vite. Wizualizacja danych wykorzystuje Chart.js (CDN). Umożliwia użytkownikom:

  • Tworzenie i zarządzanie nawykami - dodawaj własne nawyki do śledzenia
  • Wizualizację postępów - wykresy i statystyki w czasie rzeczywistym
  • Śledzenie dzienne - zaznaczaj wykonane nawyki każdego dnia
  • Udostępnianie wyników - podziel się swoimi postępami ze znajomymi
  • Eksport danych - pobieraj swoje dane do analizy
  • Tryb ciemny/jasny - dostosuj interfejs do swoich preferencji

Stack technologiczny

Frontend

Vite + Vanilla JavaScript

Styling & Wykresy

Tailwind CSS, Chart.js (CDN)

Backend & DB

Supabase (PostgreSQL)

Tools

ESLint, PostCSS

Cel projektu

Aplikacja ma na celu pomóc użytkownikom w budowaniu pozytywnych nawyków poprzez wizualizację postępów, śledzenie streak'ów i motywowanie do ciągłości. Projekt łączy prostotę interfejsu z potężnymi funkcjami analitycznymi, pozwalając każdemu na monitorowanie i udoskonalanie swoich codziennych rutyn.

Główne funkcje

Poznaj bogatą funkcjonalność aplikacji Habits Tracker:

Zarządzanie nawykami

Twórz, edytuj i usuwaj nawyki z łatwością. Każdy nawyk może mieć własny opis i kategorizację.

Wybór dni tygodnia

Zaznacz dni w których chcesz ćwiczyć nawyk. Aplikacja będzie śledzić postępy tylko dla wybranych dni tygodnia.

Customowe kategorie i kolory

Twórz własne kategorie nawyków. Wybieraj dowolne kolory z color pickera. Zarządzaj nimi klikając prawy przycisk myszy.

Wizualizacja danych

Wykresy pokazujące postępy, streak'ów i statystyki w zależności od czasu. Analizuj swoje dane w różnych przedziałach czasowych.

Kalendarz interaktywny

Przeglądaj całą historię nawyków w formacie kalendarza. Szybko zobacz, które dni były produktywne.

Udostępnianie

Generuj shareable linki do swoich nawyków. Pokaż swoim przyjaciołom swoje postępy bez potrzeby tworzenia konta.

Eksport danych

Pobieraj swoje dane w formacie JSON do dalszej analizy w innym narzędziu. Eksport zawiera harmonogram dni.

Personalizacja

Tryb ciemny i jasny, dostosowywalne kolory i ustawienia interfejsu zgodnie ze swoimi preferencjami.

Responsywny design

Aplikacja doskonale działa na wszystkich urządzeniach - od telefonów po desktopy.

Warstwy aplikacji

  • Warstwa UI: Komponenty Vanilla JS i HTML - odpowiadają za wyświetlanie interfejsu
  • Warstwa logiki: Klasa App zarządza stanem i przepływem danych
  • Warstwa serwisów: Serwisy obsługują komunikację z Supabase, export, share i inne funkcje
  • Warstwa danych: Supabase PostgreSQL przechowuje wszystkie dane użytkowników

Biblioteki zewnętrzne

  • Chart.js (CDN) - Wizualizacja danych (wykresy słupkowe i pierścieniowe). Ładowany z CDN w index.html, nie jest zależnością npm
  • Supabase - Backend i baza danych PostgreSQL
  • Tailwind CSS - Styling
  • Vite - Build tool i dev server

Przechowywanie danych lokalnych

Aplikacja używa localStorage do przechowywania preferencji użytkownika po stronie klienta:

  • custom_categories - tablica customowych kategorii nawyków (JSON). Format: [{name, icon, created_at}, ...]
  • custom_colors - tablica customowych kolorów (JSON). Format: ["#RRGGBB", ...]
  • habitsTracker:theme - wybrana preferencja motywu: 'dark' lub 'light'

Ważne: Dane w localStorage są przechowywane tylko na urządzeniu użytkownika. Jeśli użytkownik wyczyści historię przeglądarki lub zmieni urządzenie, customowe kategorie i kolory zostaną utracone. Nawyki są zapisywane w Supabase i są dostępne z każdego urządzenia.

Baza danych

Habits Tracker wykorzystuje PostgreSQL przez Supabase do przechowywania danych o nawykach i ich wykonaniu.

Tabela: habits

Główna tabela przechowująca definicje wszystkich nawyków.

Kolumna Typ Opis
id uuid Unikalny identyfikator (primary key), generowany automatycznie
name text Nazwa nawyki (wymagane, 3-50 znaków)
description text Opis nawyki (opcjonalnie, max 200 znaków)
category text Kategoria: Wellness, Learning, Fitness, Health, Productivity, Other
color text Kolor hex do wizualizacji (domyślnie: #3b82f6)
icon text Emoji lub identyfikator ikony (opcjonalnie)
scheduled_days jsonb Tablica indeksów dni tygodnia [0-6] gdzie 0=poniedziałek, 6=niedziela. Domyślnie: [0,1,2,3,4,5,6] (codziennie)
created_at timestamptz Timestamp utworzenia (ustawiane automatycznie)
updated_at timestamptz Timestamp ostatniej aktualizacji (ustawiane automatycznie)

Tabela: progress

Tabela śledzenia codziennego wykonania nawyków.

Kolumna Typ Opis
id uuid Unikalny identyfikator (primary key), generowany automatycznie
habit_id uuid Klucz obcy do tabeli habits (ON DELETE CASCADE)
date date Data wpisu (format YYYY-MM-DD)
done boolean Czy nawyka wykonana (domyślnie: false)
created_at timestamptz Timestamp utworzenia wpisu (ustawiane automatycznie)

Ograniczenie: Unique constraint na (habit_id, date) zapobiega zduplikowanym wpisom dla tej samej nawyki w tym samym dniu.

Indeksy

Dla optymalizacji wydajności zapytań:

  • idx_progress_habit_id - indeks na kolumnie habit_id dla szybszych zapytań filtrujących po nawyku
  • idx_progress_date - indeks na kolumnie date dla szybszych zapytań zakresu dat
  • UNIQUE(habit_id, date) - unikalny indeks zapobiegający duplikatom

Bezpieczeństwo - Row Level Security (RLS)

Aplikacja włącza RLS na obu tabelach i definiuje polityki dostępu dla publicznego użytkownika:

  • SELECT: Publiczny dostęp do czytania wszystkich nawyków i postępów (dla funkcjonalności udostępniania)
  • INSERT: Możliwość dodawania nowych nawyków i wpisów postępu
  • UPDATE: Możliwość aktualizacji istniejących wpisów
  • DELETE: Możliwość usuwania nawyków i wpisów postępu

Brak wymagania autentykacji - aplikacja działa z publicznym dostępem (aplikacja vanilla JS bez systemu użytkowników)

Migracja bazy danych

Migracja początkowa znajduje się w pliku 20251112153501_create_habits_tracker_schema.sql i tworzy całą strukturę bazy danych. Wykonuje następujące operacje:

  • Tworzy tabelę habits z walidacją danych
  • Tworzy tabelę progress z constraint-ami
  • Tworzy indeksy dla optymalizacji
  • Włącza RLS na obu tabelach
  • Definiuje polityki bezpieczeństwa dla publicznego dostępu

Szybki start

Szczegółowy przewodnik po uruchomieniu aplikacji Habits Tracker na swoim komputerze.

Wymagania wstępne

Zanim zaczniesz, upewnij się, że masz zainstalowane:

  • Node.js (wersja 16+ rekomendowana, pobierz z nodejs.org)
  • npm (dostępny razem z Node.js)
  • Git (do klonowania repozytorium, pobierz z git-scm.com)
  • Konto Supabase (bezpłatne, rejestracja na supabase.com)

Aby sprawdzić czy masz zainstalowane, otwórz terminal i wpisz: node --version, npm --version, git --version

1

Klonuj repozytorium

Skopiuj projekt z GitHub-a na swój komputer:

git clone https://github.com/yourusername/HabitsTracker.git
cd HabitsTracker

Zastąp yourusername swoją nazwą użytkownika GitHub.

2

Zainstaluj zależności

Pobierz wszystkie wymagane pakiety npm:

npm install

Ta komenda tworzy folder node_modules i pobiera wszystkie biblioteki (Vite, Supabase, Tailwind, itp.).

3

Utwórz projekt Supabase

Przejdź na supabase.com i:

  1. Zaloguj się lub utwórz konto
  2. Kliknij "New Project"
  3. Wpisz nazwę projektu (np. "habits-tracker")
  4. Ustaw bazową bazę danych (PostgreSQL)
  5. Poczekaj aż projekt się zainicjalizuje (1-2 minuty)
4

Skonfiguruj zmienne środowiskowe

W Supabase dashboard:

  1. Przejdź do Settings → API
  2. Skopiuj wartość "Project URL"
  3. Skopiuj wartość "anon public" key

Teraz w folderze projektu stwórz plik .env.local i wklej:

VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Ważne: Plik .env.local jest zignorowany przez Git (.gitignore), więc twoje klucze nie będą wysłane do repozytorium.

5

Uruchom migrację bazy danych

Stwórz strukturę bazy danych:

  1. Przejdź do Supabase dashboard → SQL Editor
  2. Kliknij "New Query"
  3. Otwórz plik supabase/migrations/20251112153501_create_habits_tracker_schema.sql z projektu
  4. Skopiuj całą zawartość i wklej w SQL Editor
  5. Kliknij "Run"
  6. Sprawdź w Table Editor, czy tabele habits i progress się pojawiły
6

Uruchom serwer deweloperski

Otwórz terminal w folderze projektu i wpisz:

npm run dev

Powinieneś zobaczyć komunikat:

  VITE v5.x.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Press q to quit
7

Otwórz aplikację

Kliknij na link http://localhost:5173 lub otwórz go ręcznie w przeglądarce.

Powinieneś zobaczyć główną stronę aplikacji z listą nawyków (na początku pusta).

Weryfikacja instalacji

Aby upewnić się, że wszystko działa prawidłowo:

  • Aplikacja powinna się załadować bez błędów w konsoli przeglądarki (F12 → Console)
  • Powinieneś móc dodać nowy nawyk (przycisk "+" lub "Dodaj nawyk")
  • Nawiki powinny się zapisywać w bazie danych Supabase (sprawdź Table Editor → habits)
  • Powinieneś móc zaznaczać nawiki jako wykonane

Przydatne komendy

  • npm run dev - uruchom aplikację w trybie deweloperskim z hot-reload
  • npm run build - zbuduj aplikację do produkcji (folder dist/)
  • npm run preview - podgląd budowanej aplikacji
  • npm run lint - sprawdź kod under linterem (ESLint)
  • npm run seed - załaduj dane testowe do bazy

Troubleshooting

Problem: "Module not found" lub błędy importów

  • Uruchom: npm install ponownie
  • Usuń folder node_modules i plik package-lock.json, potem npm install

Problem: Błędy związane z Supabase

  • Sprawdź czy plik .env.local ma prawidłowe wartości (bez spacji)
  • Upewnij się, że URL zaczyna się od https://
  • Załaduj stronę ponownie (Ctrl+R lub Cmd+R)

Problem: Port 5173 już zajęty

  • Sprawdź czy inne aplikacje nie używają tego portu
  • Vite automatycznie przejdzie na następny port (np. 5174)

Problem: Aplikacja się ładuje wolno

  • Sprawdź połączenie internetowe (potrzebne do Supabase)
  • Otwórz devtools (F12) i sprawdź Network tab czy requesty się wysyłają

Następne kroki

Po pomyślnym uruchomieniu aplikacji:

  • Przeczytaj sekcję Architektura, aby zrozumieć strukturę kodu
  • Przejrzyj Komponenty i Serwisy, aby wiedzieć jak coś zmienić
  • Sprawdź Bazę danych, aby zrozumieć schemat
  • Zmodyfikuj kod i zobacz jak działa hot-reload!
